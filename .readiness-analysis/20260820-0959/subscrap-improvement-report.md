# Subscrap 상세 개선 보고서

작성 시각: 2026-08-20 09:59 +07:00  
기준 자료: 20260820-0951 서비스 유사도·우수 관행 분석, 프로젝트 연속성 기록, 자동 검사 기록 334/334  
범위: 개선안을 상세화하는 분석 문서다. 제품 코드·설정·의존성·배포·GitHub·GCP·휴대폰은 변경하지 않았다.

## 1. 한 장 요약

Subscrap은 “내가 쓰는 유료서비스를 찾아서 한곳에서 관리하게 해 주는 앱”이다. 기능과 보안의 바탕은 이미 강하다. 다음 완성도를 올릴 핵심은 새 탐지 방법을 늘리는 것보다 **발견된 결과를 사용자가 믿고 행동할 수 있게 만드는 것**이다.

가장 먼저 할 개선은 후보 카드다. 사용자가 Gmail 또는 Google Play에서 찾은 항목을 볼 때, “어디에서 찾았는지·언제 결제됐는지·얼마인지·왜 후보인지·내가 지금 무엇을 눌러야 하는지”가 한 화면에서 보여야 한다. 이 한 가지가 신뢰, 정확성, 해지 전환, 고객 문의 감소를 함께 높인다.

## 2. 현재 강점

1. 직접 등록, Gmail 영수증 후보, Google Play 구독·구매 자료를 함께 다룬다.
2. Gmail과 Google Play 권한을 한 번에 섞지 않고 목적별로 분리한다.
3. 메일 원문을 저장하지 않도록 설계하고, 접근 열쇠는 암호화해 보관한다.
4. 중복 탐지, 사용자 격리, 연결 해제 정리, 과도한 Play 자료 방어가 자동 검사에 포함된다.
5. Gmail 일시 오류가 있어도 최대 3회 재시도하고, 한 항목의 실패가 전체 탐색을 멈추지 않게 한다.
6. 공개 기록상 v0.21.2, 자동 검사 334/334가 확인되어 있다.

## 3. 개선이 필요한 이유

현재 서비스는 “찾을 수 있다”는 기능은 갖췄지만, 사용자는 다음을 바로 알고 싶다.

- 이 항목은 Gmail에서 찾은 것인가, Google Play에서 찾은 것인가?
- 실제 구독인가, 한 번 결제한 것인가?
- 마지막 결제는 언제였고 다음 결제는 언제인가?
- 잘못 찾았다면 안전하게 무시할 수 있는가?
- 해지를 누르면 실제로 해지되는가, 어디서 확인해야 하는가?

이 질문에 화면이 즉시 답하지 못하면, 탐지 정확도가 높아도 사용자는 앱을 신뢰하기 어렵다.

## 4. 개선 원칙

| 원칙 | 쉬운 뜻 | 적용 기준 |
|---|---|---|
| 이유를 먼저 | 결과보다 근거를 먼저 보여 준다 | 모든 후보에 출처·날짜·금액·판단 이유 표시 |
| 사용자가 결정 | 자동 결과가 바로 확정되지 않는다 | 확정·무시·나중에 보기 제공 |
| 한계를 숨기지 않기 | 못 찾는 결제도 분명히 말한다 | Apple·카드·다른 메일 계정 안내 |
| 해지는 확인까지 | 안내와 실제 해지를 구분한다 | 공식 해지 링크 뒤 확인 체크리스트 |
| 최소 수집 | 필요한 정보만 처리한다 | 원문 미보관·권한 분리 유지 |
| 증거로 판단 | 완료 선언은 검사·실증 뒤에 한다 | 기능 검사, 실제 기기, 운영 증거 분리 |

## 5. 최우선 개선 1 — 후보 근거 카드

### 문제

후보가 목록에 나타났을 때 사용자는 “왜 이 항목이 구독 후보인지”를 바로 이해하기 어렵다. 이는 잘못된 후보를 확정하거나, 맞는 후보를 무시하는 위험을 만든다.

### 개선안

각 후보에 다음 정보를 한 카드로 표시한다.

| 표시 항목 | 예시 | 사용자 효과 |
|---|---|---|
| 발견 출처 | Gmail 영수증 / Google Play 구독 / Google Play 구매 | 어디서 온 정보인지 이해 |
| 발견 이유 | 반복 결제 문구와 결제 금액이 확인됨 | 후보가 된 근거 확인 |
| 결제 시각 | 2026-08-18 | 최신성 판단 |
| 금액·통화 | US$22 / 월 환산 참고 | 지출 판단 |
| 상태 | 구독 후보 / 일반 구매 / 확인 필요 | 자동 판단의 한계 이해 |
| 신뢰도 | 높음·보통·낮음 | 빠른 검토 순서 결정 |
| 행동 | 확정 / 무시 / 직접 수정 / 해지 안내 | 사용자가 즉시 결정 |

### 완료 기준

- 후보 목록의 모든 항목에 출처와 상태가 표시된다.
- 사용자는 한 번의 탭으로 확정·무시·직접 수정을 선택할 수 있다.
- 무시는 원래 탐지 원문을 보관하지 않고 최소 식별값만으로 중복 재표시를 줄인다.
- 자동 검사에 높은·보통·낮음 신뢰도와 각 행동 결과가 포함된다.

### 위험과 방어

신뢰도 점수를 과장하면 사용자가 자동 결과를 사실로 오해할 수 있다. 숫자 점수보다 “높음·보통·낮음”처럼 설명형 등급을 우선하고, 항상 “확인 후 등록”을 보여 준다.

## 6. 최우선 개선 2 — 탐지 범위 밖 안내

### 문제

Google 로그인 후에도 카드 결제, Apple 결제, 다른 Gmail 계정, 영수증 없는 자동결제는 누락될 수 있다. 이를 첫 화면과 빈 결과 화면에서 충분히 알려주지 않으면 “전부 찾았다”는 오해가 생긴다.

### 개선안

다음 세 곳에 같은 뜻의 짧은 안내를 둔다.

1. Google 연결 직전: “이 연결은 허용한 Gmail·Google Play 자료만 찾습니다.”
2. 탐색 완료 후: “Apple·카드·다른 메일 계정 결제는 직접 추가하거나 해당 계정에서 확인하세요.”
3. 결과가 없을 때: “찾지 못했다고 결제가 없는 것은 아닙니다.”

### 완료 기준

- 연결 전·결과 화면·빈 결과 화면에 범위 안내가 있다.
- 안내에는 Apple, 카드, 다른 메일 계정이라는 구체적 예가 있다.
- 직접 등록 화면으로 바로 갈 수 있는 버튼이 있다.

## 7. 최우선 개선 3 — 해지 확인 체크리스트

### 문제

Subscrap은 해지를 도울 수 있지만, 실제 결제 중단은 서비스 공식 페이지와 결제수단에서 다시 확인해야 한다. 이 차이를 행동 흐름에서 더 분명히 해야 한다.

### 개선안

해지 안내 뒤에 아래 네 단계의 확인 목록을 둔다.

1. 공식 해지 페이지 또는 앱 설정에서 해지를 요청한다.
2. 해지 완료 화면 또는 확인 메일을 보관한다.
3. 다음 결제 예정일을 기록한다.
4. 다음 카드·계좌 명세서에서 실제 청구가 멈췄는지 확인한다.

### 완료 기준

- “해지 안내 열기”와 “해지 완료”라는 말이 구분된다.
- 완료 체크는 실제 결제 중단을 보증하지 않는다고 표시한다.
- 다음 결제일 이후 재청구 확인 알림을 선택할 수 있다.

## 8. 개선 4 — 여러 Google 계정 관리

### 문제

가족·개인·업무 계정이 섞이면 어느 계정에서 찾은 결과인지 혼동하기 쉽다. Google Play는 다른 계정에 구독이 있을 수 있다는 점도 공식적으로 안내한다.

### 개선안

- 계정 카드마다 Gmail 연결 상태, Play 연결 상태, 마지막 탐색 시각을 따로 표시한다.
- 결과마다 계정 별칭을 표시하되 이메일 전체 주소는 불필요하게 노출하지 않는다.
- “이 항목이 없다면 다른 Google 계정으로 전환해 보세요”를 Play 결과에 표시한다.

### 완료 기준

- 계정 간 결과가 섞이지 않는다.
- 연결 해제 시 해당 계정의 토큰·작업·후보가 함께 정리된다.
- 사용자 화면과 자동 검사에서 계정 격리를 확인한다.

## 9. 개선 5 — 직접 등록을 더 빠르게

### 문제

자동 탐지가 못 찾는 결제는 결국 직접 등록이 필요하다. 직접 등록이 느리면 사용자는 누락을 방치한다.

### 개선안

- 서비스명만 먼저 입력하고 나머지는 나중에 보완하는 빠른 등록을 제공한다.
- 반복 주기·다음 결제일·금액·통화는 추천값을 주되 사용자가 수정한다.
- 가족 공유, 무료 체험 종료일, 계약 종료일은 선택 항목으로 둔다.

### 완료 기준

- 필수 입력은 서비스명·금액·주기 세 가지 이하로 시작한다.
- 입력 중단 후에도 임시 내용이 사라지지 않는다.
- 수동 등록 항목도 후보 항목과 같은 합계·결제일·해지 흐름에 들어간다.

## 10. 개선 6 — 알림과 절약 기회의 설명력

### 문제

알림이 많으면 무시되고, 절약 추천 이유가 약하면 사용자가 신뢰하지 않는다.

### 개선안

- 알림마다 이유를 표시한다: 무료 체험 종료, 다음 결제일, 90일 미사용, 가격 상승, 중복 후보.
- 절약 기회는 예상 절약액만 말하지 말고 계산 근거를 함께 보여 준다.
- 알림 빈도는 사용자별로 조절한다.

### 완료 기준

- 모든 알림에 발생 이유가 있다.
- 절약 계산은 기간·통화·기준 금액을 보여 준다.
- 사용자가 알림을 끄거나 시점을 바꿀 수 있다.

## 11. 개선 7 — 개인정보와 신뢰 문구

### 문제

Google 권한은 사용자가 민감하게 느낄 수 있다. 기술적으로 안전해도, 설명이 어렵다면 연결하지 않는다.

### 개선안

- 권한 요청 직전에 “읽는 것·저장하지 않는 것·언제 삭제되는 것”을 세 문장으로 설명한다.
- Gmail과 Play 권한을 따로 요청하는 이유를 명시한다.
- 연결 해제의 결과를 확인 창에서 설명한다.
- 개인정보 정책·문의·데이터 삭제 경로를 한 화면에서 찾게 한다.

### 완료 기준

- 권한 화면이 기술 용어 없이도 이해된다.
- 원문 미보관, 암호화된 접근 열쇠, 연결 해제 삭제가 실제 동작과 문서에서 일치한다.
- 외부 개인정보·보안 검토 여부는 확인 전까지 “미확인”으로 표시한다.

## 12. 개선 8 — 운영 신뢰와 지원

### 문제

자동 검사는 강하지만 실제 사용자 문의, 장애 대응, 복구 훈련의 증거가 아직 부족하다.

### 개선안

- 사용자가 볼 수 있는 서비스 상태·최근 오류 안내를 준비한다.
- Gmail·Play 탐색 실패 시 재시도 가능 시점과 대체 행동을 안내한다.
- 운영자용 장애 대응표와 복구 훈련 기록을 만든다.
- 개인정보 관련 문의·삭제 요청의 처리 흐름을 문서화한다.

### 완료 기준

- 오류가 나도 사용자가 다음 행동을 알 수 있다.
- 정기 복구 훈련의 날짜·결과·개선점이 남는다.
- 지원 문의를 받을 실제 채널과 책임자가 정해진다.

## 13. 개선 9 — 결제와 상용화 준비

### 문제

가격 안내는 있으나 실제 결제 제공자의 승인·거절·환불·복원 시험 증거는 아직 없다. 이 상태에서 상용화 99%라고 말하면 근거가 부족하다.

### 개선안

- 결제 전 화면에 가격, 청구 주기, 세금, 무료 체험, 자동 갱신, 해지, 환불을 모두 표시한다.
- 결제 제공자 샌드박스에서 승인·거절·중복 결제·환불·복원 흐름을 시험한다.
- 사업자 정보, 고객 지원, 개인정보·환불 정책을 확정한다.

### 완료 기준

- 결제 버튼 바로 전에 총액과 조건이 보인다.
- 샌드박스 시험이 자동 또는 재현 가능한 절차로 기록된다.
- 실제 결제 시작 전 법률·세무·환불 정책의 검토 상태가 명확하다.

## 14. 개선 10 — 기기·브라우저 실증

### 문제

공개 웹과 자동 검사는 강하지만, 설치형 Android, iPhone, Firefox, Safari의 실제 사용 증거는 부족하다.

### 개선안

- 실제 기기 시험은 유휴 A56 `R5CY32TNJFM` 한 대만 먼저 사용한다.
- 설치, 업데이트, 전체 화면, 오프라인, Google 연결 화면, 해지 안내 흐름을 확인한다.
- 이후 iPhone Safari, Firefox, Safari PC를 별도 표본으로 확인한다.

### 완료 기준

- 기기·브라우저별 시험 항목과 결과가 기록된다.
- 실패 시 화면·재현 절차·수정 여부가 남는다.
- 두 번째 Android 폰은 사용하지 않는다.

|---|---|---|
| 후보 확정률 | 탐지 후보 중 사용자가 구독으로 인정한 비율 | 출처별로 분리해 추적 |
| 후보 무시율 | 잘못되었거나 불필요한 후보 비율 | 높은 출처·유형을 개선 |
| 후보 검토 시간 | 후보를 보고 확정·무시까지 걸린 시간 | 카드 도입 전후 비교 |
| 직접 등록 전환 | 자동 탐지 밖 결제를 추가한 비율 | 범위 안내의 효과 확인 |
| 해지 안내 완료율 | 해지 안내를 연 뒤 체크리스트를 완료한 비율 | 실제 해지 보장과 구분 |
| 재청구 신고율 | 해지 뒤 다시 청구됐다고 표시한 비율 | 안내·알림 품질 확인 |
| 탐색 성공률 | Gmail·Play 탐색이 정상 완료된 비율 | 오류 재시도 효과 확인 |
| 지원 해결 시간 | 문의 접수부터 해결까지 시간 | 운영 준비도 확인 |

개인정보 원칙상 이 지표는 가능하면 집계값으로만 보고, 메일 원문이나 불필요한 결제 세부내용을 운영 분석에 사용하지 않는다.

## 17. 위험 관리

| 위험 | 예방 | 실패했을 때 |
|---|---|---|
| 후보를 사실로 오해 | 후보·확정 상태 분리, 근거 표시 | 무시·수정·신고 제공 |
| 모든 결제를 찾는다고 오해 | 범위 밖 안내 반복 | 직접 등록·플랫폼 확인으로 연결 |
| 해지 완료 오해 | 안내와 실제 해지 구분 | 다음 청구일·명세서 확인 안내 |
| 권한 불안 | 최소 권한·원문 미보관 설명 | 연결 해제·데이터 삭제 경로 제공 |
| 외부 API 오류 | 재시도·항목별 계속 처리 | 재시도 시점·상태 표시 |
| 운영 과장 | 자동 검사와 실제 실증 분리 | 미확인 항목을 예비로 표시 |

## 18. 의사결정 요청

다음 개발 묶음으로 1단계의 후보 근거 카드·확정/무시·탐지 한계 안내를 채택하는 것이 가장 합리적이다. 이 작업은 기존 Google 탐지의 안전 원칙을 바꾸지 않고 사용자 신뢰를 크게 높인다.

결제 상용화와 실제 기기 시험은 외부 계정·정책·실제 기기 환경이 필요하므로, 별도 실행 증거를 쌓은 뒤에만 완료로 판단한다.

## 19. 이번 보고서의 한계

이 문서는 기존 코드·문서·자동 검사·공개 기록을 해석한 개선 계획이다. 실제 Gmail 원문, 사용자 결제 내역, 휴대폰, 결제 계정은 사용하지 않았다. 따라서 사용자 행동 지표와 상용 운영 결과는 측정 전까지 목표이지 실제 성과가 아니다.

## 20. 결론

Subscrap은 안전하게 후보를 찾는 기반을 갖췄다. 이제 가장 중요한 것은 더 많이 찾는 것이 아니라, **각 후보가 왜 나왔는지 분명히 보여 주고 사용자가 안심하고 확정·무시·해지 확인을 하게 만드는 것**이다. 후보 근거 카드와 탐지 범위 안내를 먼저 완성하면, 이후의 결제·운영·기기 실증도 훨씬 신뢰성 있게 진행할 수 있다.
